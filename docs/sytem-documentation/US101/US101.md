# US110 - Create a Flight Route

## 1. Requirements Engineering

### 1.1. User Story Description

As a Backoffice Operator, I want to register an aircraft model with specifications including manufacturer, model name, seating capacity, fuel capacity, maximum range, and cruising speed.

### 1.2. Customer Specifications and Clarifications 

- **Manufacturer Handling:** Manufacturers will not be managed as an entity in the application. The manufacturer must come from a fixed list (either by configuration or hardcoded per application version)
- **Seating Capacity:** The same airplane model can have different seat configurations, and therefore different capacities. The Aircraft Model should define a base/standard seating capacity, but the exact seating capacity will be defined at the specific Aircraft instance level.

### 1.3. Acceptance Criteria

- **AC1:** The system must validate that the chosen manufacturer belongs to the predefined fixed list.
- **AC2:** Numeric specifications (seating capacity, fuel capacity, maximum range, cruising speed) must be strictly positive values.
- **AC3:** Only authenticated users with the 'Backoffice Operator' role can perform this operation (requires JWT authorization).
- **AC4:** The API endpoint must follow RESTful principles, returning an appropriate HTTP status code (e.g., "201 Created") on success..

### 1.4. Found out Dependencies

* **Dependency to WP#0A - Setup:** The fixed list of Aircraft Manufacturers must be loaded into the system (Bootstrapped) before a Backoffice Operator can register an Aircraft Model.

### 1.5 Input and Output Data

**Input Data:**
- Selected data:
  - Manufacturer (from a pre-existing list).

- Typed data:
  - Model Name
  - Standard Seating Capacity
  - Fuel Capacity
  - Maximum Range
  - Cruising Speed

**Output Data:**
- Success message / "201 Created" HTTP Status
- JSON representation of the created Aircraft Model (DTO).

### 2.2. Other Remarks

Following Domain-Driven Design (DDD) principles, the `AircraftModel` entity acts as the Aggregate Root. To ensure consistency, the manufacturer must be validated against a predefined fixed configuration list during initialization, as it is not managed as a dynamic entity within the application. All technical specifications must also enforce strict validation rules to maintain valid domain states from inception.


## 3. Design - User Story Realization

### 3.1. Rationale

**The rationale grounds on the SSD interactions and the identified input/output data.**

|| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the HTTP POST request and JSON payload? | `AircraftModelRestController` | **Controller (REST):** Acts as the API entry point, isolating the network layer from business logic. |
| Step 2 | ...converting the incoming JSON payload into an intermediate format? | `CreateAircraftModelDTO` | **Data Transfer Object (DTO):** Encapsulates data transmitted over the network without exposing the domain model. |
| Step 3 | ...coordinating and executing the creation process? | `CreateAircraftModelService` | **Application Service:** Orchestrates the use case logic, interacting with the domain and repositories. |
| Step 4 | ...validating the manufacturer value? | `ModelDesignation` / `ManufacturerConfig` | **Information Expert:** The configuration holds the allowed list, and the Value Object enforces its own validation constraints. |
| Step 5 | ...instantiating the new Aircraft Model entity? | `AircraftModel` | **Creator / Factory:** Handles its own complex initialization and ensures it enters a valid state. |
| Step 6 | ...persisting the new aggregate root? | `AircraftModelRepository` | **Repository:** Encapsulates the persistence layer mechanisms to save the aggregate. |
| Step 7 | ...mapping the saved domain entity back to an external response format? | `AircraftModelAssembler` | **Assembler:** Decouples internal domain structures from external response structures. |
| Step 8 | ...returning the HTTP response to the client? | `AircraftModelRestController` | **Controller:** Formats the final DTO representation and sends a `201 Created` status code. |

## 5. Construction (Implementation)

### 5.1. Domain Layer Excerpt

@Embeddable
public class ModelDesignation implements ValueObject {
    private String manufacturer;
    private String modelName;

    protected ModelDesignation() {}

    public ModelDesignation(String manufacturer, String modelName) {
        if (manufacturer == null || modelName == null || modelName.trim().isEmpty()) {
            throw new IllegalArgumentException("Manufacturer and model name cannot be empty.");
        }
        this.manufacturer = manufacturer;
        this.modelName = modelName;
    }
}

### 5.2. Domain Layer Excerpt

@Repository
public interface AircraftModelRepository extends CrudRepository<AircraftModel, Long> {
    Optional<AircraftModel> findByDesignationModelName(String modelName);
}


## 6. Integration and Demo 

The AircraftModel endpoint integrates directly with Spring Security and requires the ROLE_BACKOFFICE_OPERATOR authority via JWT validation.

Initial bootstrapping data for valid manufacturers can be pre-loaded through the Bootstrapper class executing on startup to populate testing profiles.


## 7. Observations

To further streamline optimization and avoid duplication, a future enhancement could implement a dedicated validation annotation for matching input manufacturers directly against application configuration property files.
