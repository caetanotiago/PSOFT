### 1. Requirements Engineering

#### 1.1. User Story Description

As an Air Transport Company Collaborator (ATCC), I want to register a specific aircraft instance with details such as registration number, model, manufacturing date, and current status (active, inactive, under maintenance).

#### 1.2. Customer Specifications and Clarifications 

- **Seating Capacity Configuration:** According to client clarifications (Forum Conversation 004), the same airplane model can have different seat configurations. Therefore, the specific seating capacity must be defined and registered at the *Aircraft* instance level, overriding or complementing the standard capacity defined in the *Aircraft Model*.
- **Aircraft States:** The aircraft status must be initialized upon registration. Available initial states mentioned are: active, inactive, or under maintenance. (Note: "in-flight" is also a valid state for future iterations, but not applicable during initial registration).

#### 1.3. Acceptance Criteria

- **AC1:** The system must verify that the selected *Aircraft Model* exists in the system.
- **AC2:** The aircraft Registration Number must be strictly unique across the entire system and follow standard aviation formatting validation.
- **AC3:** The exact seating capacity for this specific instance must be provided and must be a strictly positive integer.
- **AC4:** The manufacturing date cannot be in the future.
- **AC5:** Only authenticated users with the 'ATCC' role can perform this operation (requires JWT authorization).
- **AC6:** The API endpoint must follow RESTful principles, returning "201 Created" on success.

#### 1.4. Found out Dependencies

- **Dependency to WP#1A - US101:** This User Story heavily depends on US101 (Register Aircraft Model). An aircraft instance cannot be created without a pre-existing valid Aircraft Model to be linked to.

#### 1.5 Input and Output Data

**Input Data:**
- Selected data:
  - Aircraft Model (identified by its Model Name/Designation).

- Typed data: 
  - Registration Number
  - Manufacturing Date
  - Current Status
  - Seating Capacity

**Output Data:**
- Success message / "201 Created" HTTP Status.
- JSON representation of the created Aircraft (DTO).

## 3. Design - User Story Realization

### 3.1. Rationale

**The rationale grounds on the SSD interactions and the identified input/output data.**

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the HTTP POST request and JSON payload? | `AircraftRestController` | **Controller (REST):** Acts as the entry point for the API, separating presentation from business logic. |
| Step 2 | ...converting the JSON payload into a format the domain understands? | `CreateAircraftDTO` | **DTO (Data Transfer Object):** Carries data between processes to reduce coupling. |
| Step 3 | ...coordinating the aircraft registration logic? | `CreateAircraftService` | **Application Service / Use Case Controller:** Orchestrates domain objects to fulfill the specific use case without containing business logic itself. |
| Step 4 | ...verifying if the associated aircraft model exists? | `AircraftModelRepository` | **Repository:** Accesses the persistence layer to find the referenced entity by its identifier or designation. |
| Step 5 | ...verifying if the registration number is unique? | `AircraftRepository` | **Repository:** Queries the database to prevent duplicate business keys or natural identities. |
| Step 6 | ...instantiating the new specific Aircraft instance? | `Aircraft` | **Creator:** Responsible for creating the complex aggregate root entity and ensuring it starts in a valid state with its customized seating capacity. |
| Step 7 | ...saving the new aircraft instance to the database? | `AircraftRepository` | **Repository:** Persists the newly created aggregate root. |
| Step 8 | ...mapping the saved domain object back to an external response format? | `AircraftAssembler` | **Assembler:** Decouples internal domain structures from external response structures. |
| Step 9 | ...returning the response to the client? | `AircraftRestController` | **Controller:** Formats the DTO and sends the HTTP response (`201 Created`). |
