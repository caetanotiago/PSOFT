# US115 - Create Maintenance Template

## 1. Requirements Engineering

### 1.1. User Story Description

As a Maintenance Technician, I want to create maintenance templates with details including template name, template type (inspection, scheduled maintenance, overhaul, modification), applicable aircraft models, and checklist.

### 1.2. Customer Specifications and Clarifications

- **Clarification from Forum (Conversation 016):** The maintenance intervals (flight hours and calendar days) must be attributes of the Maintenance Template. The system will look at these limits to automatically send an alert to the team every time an aircraft reaches them.

### 1.3. Acceptance Criteria

- **AC1:** The template must include valid maintenance intervals (flight hours and/or calendar days).
- **AC2:** The template type must be one of the specified categories (inspection, scheduled maintenance, overhaul, modification).
- **AC3:** The system must verify that the applicable Aircraft Models exist.
- **AC4:** Only authenticated users with the 'Maintenance Technician' role can perform this operation (requires JWT authorization).
- **AC5:** The API endpoint must follow RESTful principles, returning "201 Created" on success.

### 1.4. Found out Dependencies

- **Dependency to WP#1A (Aircraft Management):** This US depends on the existence of Aircraft Models (US101), as the template needs to be linked to the models it applies to.

### 1.5 Input and Output Data

**Input Data:**
- Typed data (via JSON payload):
    - Template Name
    - Template Type
    - Flight Hours Interval
    - Calendar Days Interval
    - Checklist (list of tasks)
- Selected data:
    - List of applicable Aircraft Model designations.

**Output Data:**
- Success message / "201 Created" HTTP Status.
- JSON representation of the created Maintenance Template (DTO).

## 3. Design - User Story Realization

### 3.1. Rationale

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the HTTP POST request? | `MaintenanceTemplateRestController` | **Controller:** Acts as the API entry point. |
| Step 2 | ...coordinating the template creation logic? | `CreateMaintenanceTemplateService` | **Application Service:** Orchestrates domain objects to fulfill the use case. |
| Step 3 | ...verifying if the applicable Aircraft Models exist? | `AircraftModelRepository` | **Repository:** Accesses the persistence layer to find models. |
| Step 4 | ...instantiating the new Template? | `MaintenanceTemplate` | **Creator:** Responsible for creating the aggregate root entity. |
| Step 5 | ...saving the new template? | `MaintenanceTemplateRepository` | **Repository:** Persists the newly created aggregate root. |
| Step 6 | ...returning the response? | `MaintenanceTemplateRestController` | **Controller:** Formats the DTO and sends the HTTP response. |
