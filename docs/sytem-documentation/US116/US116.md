# US116 - View Maintenance Records of a Specific Aircraft

## 1. Requirements Engineering

### 1.1. User Story Description

As a Maintenance Technician or Fleet Manager, I want to view all maintenance records of a specific aircraft to track its technical history.

### 1.2. Customer Specifications and Clarifications

- The system must list all maintenance operations performed or scheduled for an aircraft identified by its unique Registration Number.

### 1.3. Acceptance Criteria

- **AC1:** The user must provide a valid aircraft registration number.
- **AC2:** If the aircraft has no maintenance records, the system must return an empty list with HTTP Status 200 OK.
- **AC3:** The system must return the complete history, including description, start date, duration, component category, and completion notes (if the maintenance is already concluded).
- **AC4:** Only authorized users (Maintenance Technician or Fleet Manager) can access this information.

### 1.4. Found out Dependencies

- **Dependency to Aircraft Aggregate:** Relies on the existence of the Aircraft instance to validate the registration number.
- **Dependency to US115b:** Relies on the previous creation of maintenance records to populate the list.

### 1.5 Input and Output Data

**Input Data:**
- Aircraft Registration Number (via URL Path Variable).

**Output Data:**
- HTTP 200 OK Status.
- JSON list of Maintenance Record DTOs with HATEOAS links.

## 3. Design - User Story Realization

### 3.1. Rationale

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the HTTP GET request? | `MaintenanceController` | **Controller:** Acts as the API entry point for handling incoming requests. |
| Step 2 | ...coordinating the retrieval logic? | `ViewAircraftMaintenanceRecordsUseCase` | **Application Service (Use Case):** Coordinates the business flow, isolating the logic for this specific user story. |
| Step 3 | ...fetching the records from the database? | `MaintenanceRecordRepository` | **Repository:** Encapsulates the persistence mechanism to query records by registration number. |
| Step 4 | ...converting the entities to a readable format with HATEOAS links? | `MaintenanceRecordAssembler` | **DTO Assembler:** Responsible for transforming Domain Objects into Data Transfer Objects and adding REST hypermedia links. |
| Step 5 | ...returning the response? | `MaintenanceController` | **Controller:** Formats the list of DTOs into an HTTP response. |

## 4. Tests

**Test 1: `ViewAircraftMaintenanceRecordsUseCase` returns a populated list for an existing aircraft.**

```java
@Test
void whenAircraftHasRecords_thenReturnDtoList() {
    // Arrange
    String registration = "CS-TVA";
    MaintenanceRecord record1 = new MaintenanceRecord(...);
    MaintenanceRecord record2 = new MaintenanceRecord(...);
    when(repository.findAllByAircraftRegistration(registration)).thenReturn(List.of(record1, record2));
    when(assembler.toModel(any(MaintenanceRecord.class))).thenCallRealMethod(); // or mock the DTO conversion

    // Act
    List<MaintenanceRecordOutputDto> result = useCase.execute(registration);

    // Assert
    assertThat(result).hasSize(2);
    verify(repository, times(1)).findAllByAircraftRegistration(registration);
}
```

**Test 2: `ViewAircraftMaintenanceRecordsUseCase` returns an empty list for an aircraft with no records.**

```java
@Test
void whenAircraftHasNoRecords_thenReturnEmptyList() {
    // Arrange
    String registration = "CS-TVB";
    when(repository.findAllByAircraftRegistration(registration)).thenReturn(Collections.emptyList());

    // Act
    List<MaintenanceRecordOutputDto> result = useCase.execute(registration);

    // Assert
    assertThat(result).isEmpty();
}
```

## 5. Construction (Implementation)

The implementation followed the design precisely. The `MaintenanceRecordRepository` was updated with the `findAllByAircraftRegistration` method, which Spring Data JPA implements automatically. A dedicated use case, `ViewAircraftMaintenanceRecordsUseCase`, was created to orchestrate the logic, and the `MaintenanceController` exposes the final endpoint. The `MaintenanceRecordAssembler` handles the conversion to `MaintenanceRecordOutputDto` and adds HATEOAS links, fulfilling the REST maturity requirement.

## 6. Integration and Demo

To demonstrate this User Story, one can perform a GET request to the endpoint `/api/maintenance-records/aircraft/{registration}` using a tool like Postman or cURL.

**Example Request:**
`GET http://localhost:8080/api/maintenance-records/aircraft/CS-TVA`

**Expected Success Response (200 OK):**
```json
[
    {
        "id": 1,
        "aircraftRegistration": "CS-TVA",
        "maintenanceTemplateId": 101,
        "recordDetails": { ... },
        "component": { ... },
        "completionNotes": null,
        "_links": {
            "self": { "href": "http://localhost:8080/api/maintenance-records/1" },
            "complete": { "href": "http://localhost:8080/api/maintenance-records/1/complete" }
        }
    }
]
```

If the aircraft has no records, the system will return an empty array `[]` with a 200 OK status.

## 7. Observations

This endpoint is read-only and does not modify any state, making it a safe and idempotent operation. The use of a dedicated use case class improves code organization and aligns with the Clean Architecture principles of the project. The HATEOAS links provide clients with discoverable actions, improving the API's usability.
