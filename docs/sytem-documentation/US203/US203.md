# US203 - View compatible routes for a specific aircraft

## 1. Requirements Engineering

### 1.1. User Story Description

As an ATCC, I want to view which routes are compatible with a specific aircraft based on its range and capacity.

### 1.2. Customer Specifications and Clarifications

- **Clarification:** The seating capacity belongs to the specific physical `Aircraft` instance, while the maximum flight range is defined in the `AircraftModel` catalog.
- **Business Rule:** A route is considered compatible with an aircraft if and only if:
  1. The `Aircraft`'s seating capacity is greater than or equal to the `Route`'s required capacity.
  2. The `AircraftModel`'s maximum range is greater than or equal to the `Route`'s distance.
- **Non-Functional Requirement:** Long result lists must support pagination.

### 1.3. Acceptance Criteria

- **AC1:** The system must return a paginated list of routes matching the capacity and range criteria of the specified aircraft.
- **AC2:** If the provided aircraft registration does not exist, the system must return `404 Not Found`.
- **AC3:** The endpoint follows RESTful principles (`GET /api/aircrafts/{registrationNumber}/compatible-routes`) and is restricted to users with the `ATCC` role.

### 1.4. Found out Dependencies

- **Dependency to US102:** The physical `Aircraft` must be registered in the system.
- **Dependency to US110:** The `FlightRoute` entities must exist to be evaluated.

### 1.5 Input and Output Data

**Input Data:**
- **Path Variable:** Aircraft Registration Number (e.g., "CS-ABC").
- **Query Parameters:** Pagination details (`page`, `size`).

**Output Data:**
- Paginated JSON list of compatible `FlightRouteDTO` representations.
- HTTP Status `200 OK`.

## 3. Design - User Story Realization

### 3.1. Rationale

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the GET request? | AircraftController | **Controller (REST):** Handles requests targeting aircraft resources. |
| Step 2 | ...coordinating the compatibility check? | ViewCompatibleRoutesService | **Application Service:** Orchestrates the flow between distinct domain aggregates. |
| Step 3 | ...retrieving the aircraft details? | AircraftRepository | **Repository:** Fetches the Aircraft entity by registration. |
| Step 4 | ...finding matching routes? | FlightRouteRepository | **Repository:** Executes an optimized database query to filter routes based on provided thresholds. |
| Step 5 | ...returning the response? | FlightRouteAssembler | **Assembler:** Converts the fetched Route entities into DTOs containing HATEOAS links. |

## 7. Observations

Executing the filtering at the database layer (via JPQL query) instead of fetching all routes into memory is a deliberate architectural decision to ensure the system scales linearly with the route catalog size.
