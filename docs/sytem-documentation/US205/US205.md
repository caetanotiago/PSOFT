# US205 - View real-time aircraft availability status

## 1. Requirements Engineering

### 1.1. User Story Description

As an ATCC, I want to view real-time aircraft availability status (available, in-flight, under maintenance, inactive).

### 1.2. Customer Specifications and Clarifications

- **Clarification:** In this iteration, the state transitions are handled manually (via US105). The system simply needs to expose an endpoint to retrieve the current operational state of a specific aircraft.
- **Business Rule:** The status returned must reflect the exact current value of the `AircraftStatus` Value Object associated with the `Aircraft` aggregate.

### 1.3. Acceptance Criteria

- **AC1:** The system must return the real-time status of the requested aircraft.
- **AC2:** If the provided aircraft registration does not exist, the system must return `404 Not Found`.
- **AC3:** The endpoint follows RESTful principles (`GET /api/aircrafts/{registrationNumber}/status`) and is restricted to users with the `ATCC` role.

### 1.4. Found out Dependencies

- **Dependency to US102:** The aircraft must be previously registered in the system.
- **Dependency to US105:** Depends on the manual update feature to effectively see status variations.

### 1.5 Input and Output Data

**Input Data:**
- **Path Variable:** Aircraft Registration Number (e.g., "CS-ABC").

**Output Data:**
- JSON object containing the status (e.g., `{ "registration": "CS-ABC", "status": "IN_FLIGHT" }`).
- HTTP Status `200 OK`.

## 3. Design - User Story Realization

### 3.1. Rationale

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the HTTP GET request? | AircraftController | **Controller (REST):** Entry point for aircraft-related endpoints. |
| Step 2 | ...coordinating the retrieval logic? | ViewAircraftStatusService | **Application Service:** Orchestrates the fetch operation. |
| Step 3 | ...finding the aircraft? | AircraftRepository | **Repository:** Fetches the aggregate from the persistence layer. |
| Step 4 | ...encapsulating the result? | AircraftStatusDTO | **DTO:** Transports only the strictly requested data (status string) avoiding exposing the entire Aircraft aggregate. |
| Step 5 | ...returning the response? | AircraftController | **Controller:** Formats the DTO into a JSON HTTP response. |

### Systematization

Promoted classes:
- Aircraft
- AircraftStatus (Value Object)

Pure Fabrication:
- AircraftController
- ViewAircraftStatusService
- AircraftRepository
- AircraftStatusDTO
