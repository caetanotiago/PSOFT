# US206 - Calculate total operational hours for each aircraft

## 1. Requirements Engineering

### 1.1. User Story Description

As an ATCC, I want to calculate the total operational hours for each aircraft in my fleet.

### 1.2. Customer Specifications and Clarifications

- **Clarification:** A "fleet" in this context refers to the set of all aircraft managed by the system.
- **Business Rule:** The system must aggregate the total operational hours (sum of flight durations) for every individual aircraft.
- **Non-Functional Requirement:** As the fleet and flight logs can grow significantly, the result list must support pagination. Data aggregation must be performed at the persistence layer to guarantee performance.

### 1.3. Acceptance Criteria

- **AC1:** The system must return a list of all aircraft along with their respective accumulated operational hours.
- **AC2:** Aircraft with no flights should return 0 operational hours.
- **AC3:** The result list must support pagination parameters (`page`, `size`).
- **AC4:** The endpoint follows RESTful principles (`GET /api/aircrafts/operational-hours`) and is restricted to users with the `ATCC` role.

### 1.4. Found out Dependencies

- **Dependency to US102:** Requires physical `Aircraft` instances to exist in the system.
- **Dependency to WP#3B:** Requires completed flight records (e.g., `ScheduledFlight` or `FlightHistory`) to accurately calculate the operational hours.

### 1.5 Input and Output Data

**Input Data:**
- **Query Parameters:** Pagination details (`page`, `size`).

**Output Data:**
- Paginated JSON list of `AircraftOperationalHoursDTO` (containing the aircraft registration and its total operational hours).
- HTTP Status `200 OK`.

## 3. Design - User Story Realization

### 3.1. Rationale

| Interaction ID | Question: Which class is responsible for... | Answer | Justification (with patterns) |
|:---|:---|:---|:---|
| Step 1 | ...receiving the HTTP GET request? | AircraftController | **Controller (REST):** Entry point for fleet-related endpoints. |
| Step 2 | ...coordinating the calculation? | CalculateOperationalHoursService | **Application Service:** Orchestrates the pagination and database query. |
| Step 3 | ...calculating the sum grouping by aircraft? | AircraftRepository | **Repository:** Executes an optimized JPQL `GROUP BY` query, applying pagination directly at the database level. |
| Step 4 | ...encapsulating the result? | AircraftOperationalHoursDTO | **DTO:** Transports only the strictly relevant data (registration and total hours) to the web layer. |
| Step 5 | ...returning the response? | PagedResourcesAssembler | **Assembler:** Wraps the paginated DTOs into a HATEOAS-compliant JSON response. |

## 5. Construction (Implementation)

To be completed during implementation. The core logic relies on a JPQL query in AircraftRepository such as: SELECT new AircraftOperationalHoursDTO(a.registration.registration, COALESCE(SUM(f.duration), 0)) FROM Aircraft a LEFT JOIN a.flights f GROUP BY a.registration.

## 6. Integration and Demo

Demonstrated with GET /api/aircrafts/operational-hours?page=0&size=10.

## 7. Observations

Using a LEFT JOIN and COALESCE in the JPQL query ensures that the entire fleet is returned, fulfilling the "each aircraft in my fleet" requirement, even for newly registered planes that haven't flown yet.
